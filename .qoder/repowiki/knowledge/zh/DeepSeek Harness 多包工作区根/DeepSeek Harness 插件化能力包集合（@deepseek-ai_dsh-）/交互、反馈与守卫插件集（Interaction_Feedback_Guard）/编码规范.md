- 插件通过扩展 `Context` 接口（`declare module '@deepseek-ai/cordis' { interface Context { ... } }`）向宿主注入服务键，如 `commands`、`messageFeedback`、`userQuestions`、`approval`。
- 对外暴露的服务类继承 `TypertRemoteService` 或 `Service`，并在静态成员中声明 `inject` 依赖列表与 `Config` schema（使用 schemastery/zod），在构造函数中校验配置。
- 所有可被外部调用的方法使用 `@Remote` 装饰器暴露为远程端点，入参与返回值通过 zod/schemastery schema 严格校验。
- 业务失败通过统一的 `success(value)` / `rejected(error)` 联合返回结构表达，而非抛出异常，使调用方可模式匹配处理。
- 跨进程/跨边界的数据在离开服务前使用 `Object.freeze` + 浅拷贝进行快照（如 `snapshotItem`、`rowSnapshot`、`normalizeResult`），防止可变别名泄露。
- 插件通过 `ctx.on('...')` 订阅 Cordis 事件（如 `tools/post-execute`、`tools/execute`、`agent/pre-step`）实现横切逻辑，并以 `next()` 委托下游。
- 会话审计事件统一通过 `session.append('event/type', data)` 追加，且成对出现（如 `command/run`+`command/done`、`approval/asked`+`approval/decided`），保证可重放一致性。
- 错误分类采用具名错误类（如 `UserQuestionError extends HarnessError`）配合稳定 `code` 字符串，便于调用方精确分支处理。
