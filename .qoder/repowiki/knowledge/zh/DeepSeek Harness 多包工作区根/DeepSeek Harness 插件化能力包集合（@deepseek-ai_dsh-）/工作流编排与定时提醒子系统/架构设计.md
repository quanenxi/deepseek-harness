模块由两个独立的能力家族组成，均通过 Cordis 插件机制挂载到宿主 Context。

- workflow/ 家族：以 `workflow` 包定义抽象契约 `WorkflowEngine` 及其 `workflow/*` 事件（start/phase/log/agent-start/agent-end/end）、`WorkflowError` 错误码体系与 `WorkflowRun` 接口；`workflow-worker-thread` 实现该抽象，使用 Node `vm` + `worker_threads` 在独立线程中编译并运行模型脚本，通过 `WorkerRun` 桥接 `agent()` 调用回宿主的 `ctx.subagents`，并以 `schemastery` 校验部署配置；`tool-workflow` 注册模型工具 `workflow`，将脚本参数、meta 和 args 转发给 `ctx.workflowEngine.start`，并通过监听 `workflow/*` 事件把运行记录追加到 Session；`tool-ralph` 是固定策略工具，内嵌一段不可篡改的 Ralph 循环脚本，强制使用支持结构化输出的 fresh provider，并对跨边界返回值做严格解码与截断。
- schedule/ 包：纯进程内定时器，不暴露数据库服务；`apply` 在 `agent/created` 时按 root agent 实例化 `ScheduleRuntime`，订阅 `agent/status` 并在 idle 时驱动；`runtime.ts` 通过 `foldScheduleEvents` 从当前 Session 事件流折叠出活跃计划，用 `setTimeout` 调度下一次唤醒，借助 `runMaintenance` 在 Agent 空闲阶段投递 `createUserMessage` 作为 followup，并用 `schedule/change` 事件持久化已分派状态；`persistence.ts`、`transaction.ts`、`domain.ts`、`tools.ts` 分别承担落盘、事务包装、领域建模与 create/list/delete 工具注册。

依赖方向单向：tool-* → workflow 契约 → worker-thread 实现；schedule 独立于 workflow，仅依赖 dsh-agent/dsh-session/dsh-llm。
