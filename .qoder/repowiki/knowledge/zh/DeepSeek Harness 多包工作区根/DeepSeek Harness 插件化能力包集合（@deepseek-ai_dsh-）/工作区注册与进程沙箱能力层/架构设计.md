模块由两个并列的包族组成，共同构成 DeepSeek Harness 中“工作区”和“进程沙箱”的能力边界：

- `packages/workspace/workspace`（`@deepseek-ai/dsh-workspace`）：以 `WorkspaceRegistry` Service（继承自 `@deepseek-ai/cordis` 的 `Service`）为核心，通过 `storageDomain` 打开 `workspaceDomainSpec` 定义的 KV 表 `workspaces` 与全局状态 `WorkspaceDomainState`，在 `init` 阶段执行 `recoverPendingMutation → validateStoredState → bootstrap` 三阶段启动，维护 `entities`、`headers`、`sessionPaths`、`invalidSessionPaths` 等内存索引，并通过 `enqueueOperation` 串行化所有写操作以保证持久化一致性；`WorkspaceEntity` 封装单个工作区的 session 归属与移动/删除语义。
- `packages/sandbox` 子包族按职责分层：
  - `sandbox`（`@deepseek-ai/dsh-sandbox`）：定义抽象 `SandboxProvider` 接口及 `SandboxMode`/`SandboxPolicy`/`ConfinedArgv`/`RunnerFailureRule` 等跨后端契约，暴露 `escalation.ts` 中的升级审批标记与 `roots.ts` 的路径规范。
  - `sandbox-policy`（`@deepseek-ai/dsh-sandbox-policy`）：`SandboxPolicyService` 作为唯一策略所有者，组合部署默认模式、会话 `cwd` 与 `effectiveSandboxMode(session.events)` 计算 per-call 策略，并注入 `systemPrompt.context('sandbox:policy')` 使策略随模型历史可回放。
  - `sandbox-local`（`@deepseek-ai/dsh-sandbox-local`）：`LocalSandboxProvider` 实现具体后端选择链 `PLATFORM_CHAINS`（linux→bwrap/landlock，darwin→seatbelt，win32→windows-acl），通过一次性功能探测仲裁候选者，缓存 `selectedRunner` 并维护 Windows ACL 的 standing workspace grant 与可撤销 temp grant 生命周期。
  - `sandbox-windows-acl`（`@deepseek-ai/dsh-sandbox-windows-acl`）：纯 Windows 后端，基于 `koffi` FFI 调用 Win32 API 创建 `WRITE_RESTRICTED` 受限令牌，通过 `AclWriteGrant` 对目录 DACL 追加 capability SID 的写 ACE，`workspaceWriteSid`/`tempWriteSid` 派生确定性 SID，`spawn`/`runner.ts` 负责受限 token 下的子进程创建与 stdio 管道。

依赖方向单向向下：`sandbox-local` 依赖 `sandbox` + `sandbox-windows-acl` + `node-addon-landlock-run`；`sandbox-policy` 仅依赖 `sandbox`；`workspace` 不依赖 sandbox 族，二者通过 `ctx.session`/`ctx.storageDomain` 等 cordis 服务松耦合协作。
