本模块由两个独立的 npm 包组成，均通过 `@deepseek-ai/cordis` 的 Context/Loader 服务机制对外暴露能力：
- `app-boot`（`@deepseek-ai/dsh-app-boot`）是应用二进制的启动胶水层，核心入口 `src/index.ts` 提供 `boot()` 主函数，按顺序完成：创建 Context → 安装 fail-loud 未处理拒绝处理器 → 解析并加载 `.env`（进程环境 > 项目目录 > Harness home 三层合并，禁止覆盖 bootstrap-only 变量）→ 挂载根 `cordis:include` 插件（支持 snapshot 模式将 `cordis.yml` 替换为 `cordis.snapshot.yml`）→ 调用可选 `prepare` → 等待 Loader 树 settle → 审计所有 fiber 状态并通过 `assertEntriesActivated` 抛出未激活条目 → 返回 Context。同时导出 `loadOptionalPatches` / `loadOverlayPatches` / `renderConfigDump` / `watchUserPatches` 等工具，配合 HMR 实现用户补丁文件的热重载；`profile.ts` 管理 bundle/profile 清单；`invariant.ts` 提供运行时断言。
- `cmdline`（`@deepseek-ai/dsh-cmdline`）负责 launcher 与 app 之间的命令行交接，通过 `provideCmdline(ctx, host)` 注入 `cmdlineArgs` 和 `appExit` 服务，再由 `parseCmdline(ctx, program)` 用 commander 解析 app 自有参数，并将 help/version/error 统一路由到 `ctx.appExit`，避免直接调用 `process.exit`。
依赖方向单向：两个包都依赖 `@deepseek-ai/cordis` 及其插件（loader/include/group/hmr），不反向被 cordis 引用；`app-boot` 还依赖 `dsh-home-paths`、`dsh-launch-environment`、`dsh-system-prompt` 等 workspace 内部包，`cmdline` 仅依赖 commander 作为 devDependency。
