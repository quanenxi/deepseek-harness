本模块由三个相互协作的子包组成，依赖方向自下而上：`@deepseek-ai/dsh-scope` → `@deepseek-ai/dsh-agent` → `@deepseek-ai/dsh-agent-loop`。

- `scope`（最底层）：提供无副作用的作用域原语——通过 `createScope` 在 Cordis `Context` 上打标签、用 `bindScopeParent` 建立父子链、用 `scopeTarget` 构造带路由过滤的事件载体，使事件只能从子作用域向父作用域传播，从而隔离不同 Agent 的注册与事件。
- `agent`（中间层）：定义 `Agent`/`AgentFactory`/`CreateAgentOptions`/`ResumeAgentOptions` 等契约，并通过 `AgentRegistry` 暴露 `ctx.agents`，维护已注册 Agent 的 Map、`enter/announce/register` 有序生命周期、以及基于 `AsyncLocalStorage` 的进程内发起者作用域（`withInitiator`/`withoutInitiator`/`currentInitiator`），将具体创建委托给上层插件。
- `agent-loop`（顶层实现）：`AgentLoop` 作为 Cordis `Service` 注入 `agents/sessions/llm/tools/systemPrompt`，实现 `AgentFactory` 接口并调用 `ctx.agents.setFactory`；启动时解析配置、应用 launcher 覆盖的会话身份、按 `agents` 数组并发恢复或创建 Agent；`ReactLoopAgent` 是状态机驱动的默认驱动，维护 idle/maintenance/running 三态、通过 `Inbox` 接收消息并在 turn/step 边界组装 prompt 与 tool-call 请求；`tool-calls.ts` 负责并行工具调用调度，`runtime-context.ts` 投影 session/agent 信息到系统提示变量。

三者通过 Cordis 的 Service/Context/Fiber 机制解耦：scope 不感知 agent，agent 只依赖 scope 做事件路由，agent-loop 是唯一持有 `AgentLoop` 服务实例并编排完整生命周期的实现。
