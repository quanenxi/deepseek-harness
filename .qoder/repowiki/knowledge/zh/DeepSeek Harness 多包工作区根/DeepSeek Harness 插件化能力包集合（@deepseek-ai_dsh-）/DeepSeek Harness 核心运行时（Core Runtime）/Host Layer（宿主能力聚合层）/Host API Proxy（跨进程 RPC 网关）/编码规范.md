- 每个领域 API 采用 `<domain>.ts` 定义接口 + `<domain>.schema.ts` 用 schemastery/Zod 定义请求/响应 schema 的双文件配对模式。
- 所有 RPC 方法在 `api/rpc-map.ts` 的 `RpcMethodMap` 中集中声明，`RequestPayload` 与 `ResponseValue` 泛型从该映射派生，作为类型唯一来源。
- 错误统一包装为 `{ ok: false, error: { code, message, details } }` 形式的 `RpcResponse`，通过 `err()` 辅助函数构造，业务异常在边界处映射为稳定 code。
- 成功响应通过 `ok(request, value)` 自动回显 `request.rpcId`，保持请求-响应的 rpcId 一致性。
- 可选能力（如 settings、credentials、sessionProjections、approval）通过 `ctx.get(...)` 读取并优雅降级，使部署可在缺少某提供者时仍运行其他功能。
- 对宿主事件的转发采用白名单 + JSON 值断言（`assertJsonArgs`），非 JSON 可表示的参数直接抛错而非静默丢弃。
