- 每个后端以继承 `DirectoryPicker` 的类实现 `capability()`，返回一个在 service 生命周期内稳定的能力对象，消费者可安全缓存该对象跨调用复用。
- 所有异步 I/O 操作通过 `AbortSignal` 传递调用者生命周期，并使用 `raceAbort` 或等效模式确保网络/文件系统挂起不会让已取消的请求存活。
- 错误通过统一的 `DirectoryPickerError` 抛出，并携带闭集 `DirectoryPickerErrorCode`（`directory-unreadable` / `directory-exists` / `directory-create-failed`），禁止使用任意字符串错误码。
- 路径参数在进入文件系统前强制用 `fullyQualified` 校验，拒绝相对路径或驱动未限定的 Windows 形式，避免隐式解析到进程 cwd。
- 平台差异通过运行时分支（`process.platform`）+ 可注入钩子（如 `DirectoryPickerInternals`、`canExecute`、`pickWin32Dialog`）解耦，使同一逻辑可在测试中替换实现。
- 包通过 `exports` 字段同时暴露主入口与 `./invariant`、`./worker` 等子路径，并在 `files` 白名单中显式声明发布产物。
