模块由四个协作的 Cordis 子包组成，围绕一个抽象服务定义分层：
- `directory-picker`：纯接口与抽象基类包，定义 `DirectoryPickerCapabilities` 判别联合（`native` / `browse`）、`DirectoryEntry`、`DirectoryListing`、`DirectoryPickerError` 以及继承自 `@deepseek-ai/cordis` 的 `Service` 的抽象类 `DirectoryPicker`，并通过 `declare module '@deepseek-ai/cordis'` 将 `ctx.directoryPicker` 注入 Context。
- `directory-picker-browse`：基于 Node `fs/promises` 的浏览后端，实现 `list`/`createDirectory`，使用流式 `opendir` + 名称排序有界窗口（`boundedInsert`）控制单级条目数，所有 I/O 通过 `raceAbort` 与 `AbortSignal` 绑定调用者生命周期。
- `directory-picker-native`：平台相关后端，macOS 调用 `osascript`，Linux 依次尝试 `zenity`/`kdialog`，Windows 通过 `koffi` 在子进程中调用 COM `IFileOpenDialog`（`win32-dialog.*` 拆分 host/worker/bindings/logic），统一暴露 `pickNativeDirectory`。
- `directory-picker-auto`：自适应装配插件，启动时采样 `bindHost`/`platform`/`SSH_*`/`DISPLAY`/`WAYLAND_DISPLAY`/`linuxChooser` 等主机事实，通过 `resolveDirectoryPickerBackend` 决定挂载 `native` 或 `browse` 后端及其对应客户端 UI 面，并以 `ctx.effect` 管理 Loader 条目的创建与卸载。
依赖方向单向：auto → {browse, native} → picker（接口），各后端仅依赖接口包与平台工具，不反向引用。
