模块以 `src/index.ts` 导出的 `ApiProxyService`（继承自 `@deepseek-ai/cordis` 的 `Service`）作为宿主入口，通过 `inject` 注入 `agentDefaultModel`、`sessions`、`workspaceRegistry`、`llm`、`subagents`、`tools`、`userQuestions`、`settings`、`credentials` 等域服务，并在 `Context` 上挂载 `apiProxy`。

内部按职责分层：
- `api/`：契约层。每个领域（sessions、workspace、host、goals、skills、agent-presets、settings、credentials、llm、events、downloads、jobs、questions、approvals、subagents）由一对 `<domain>.ts` + `<domain>.schema.ts` 组成，schema 使用 `@deepseek-ai/schemastery` 定义请求/响应 Zod 校验；`rpc-map.ts` 集中声明所有 RPC 方法名到域接口的映射，是 `RequestPayload`/`ResponseValue` 泛型的唯一来源；`rpc.ts` 定义 `RpcRequest`/`RpcResponse`/`RpcError` 统一信封。
- `api-proxy.ts`：实现层。`createApiProxy(ctx, defaults)` 返回 `ApiProxy` 实例，封装分页、投影、冷/热会话摘要、模型目录构建、审批/提问水线、工具 presenter 渲染、事件转发等核心逻辑，并通过 `FrameQueue` 与 `MuxFrame` 支持 session/subagent 的多路复用流式推送。
- `fetch/`：传输适配层。`handler.ts` 提供 `toFetchHandler` 把 RPC 路由到 `ctx.apiProxy`，`client.ts` 提供 `AbstractApiClient`/`InProcessApiClient` 供浏览器或同进程调用。
- `session-export.ts`、`native-path-opener.ts`、`invariant.ts`：横切工具，分别负责会话日志 ZIP 导出、原生路径打开能力探测与断言。
依赖方向单向向外：本包消费大量 `@deepseek-ai/dsh-*` 工作区包，但仅通过类型导入避免循环；对外只暴露 `lib/types` 下的类型与 `lib/index.js` 运行时。
