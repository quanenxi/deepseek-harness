模块以 `src/bin.ts` 为 Node 可执行入口（package.json `bin.dsh` → `lib/bin.js`），通过 Commander 在 `parseDshArgs` 中把 argv 解析为带判别字段的 `DshInvocation`（`profile` / `plugin` / `dump-config`），再由 switch 动态 `await import` 各模式模块，避免无关模式被打包进同一二进制。
- `args.ts`：定义 CLI 选项（`--profile`、`--patch`、`--dump-config`、`web` 别名、`plugin` 子命令），将 launcher 自身标志与透传给已启动应用的剩余参数分离。
- `profile-boot.ts`：核心编排器，按顺序组装补丁层（bundle 层 → profile 层 → `$DSH_HOME/cordis.patch.yml` → `--patch` 覆盖层 → 遥测开关），写入空根 `cordis.yml` 后调用 `@deepseek-ai/dsh-app-boot` 的 `boot()` 挂载树，并在启动后监听用户补丁文件实现 HMR；同时注入 `DSH_LAUNCH_ENVIRONMENT_KEY` 与 `ctx.cmdlineArgs` 给应用插件。
- `plugin.ts`：`dsh plugin` 子命令，先初始化 profile 目录，再 `spawnSync` 转发至 pnpm，最后根据已安装依赖是否声明 `dsh.bundle` 自动同步 `dsh.profile.bundles` 列表。
- `dump-config.ts`：不启动任何 entry 的纯配置渲染，复用 `prepareProfile` 与 include 插件的 patch 算法输出分层注释。
- `process-shutdown.ts`：统一 SIGTERM/SIGINT 处理与 fiber 析构。
构建由 `tsdown.config.ts` 指定入口 `lib/types/bin.js`，仅打包该入口及其可达模块；源码与产物共享 `config/agent-presets/` 下的预设配置文件。依赖方向单向指向 workspace 内的 `@deepseek-ai/*` 包，本模块不暴露 API 供其他包使用。
