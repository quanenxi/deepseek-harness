- 配置类统一使用 `@dataclass(slots=True)` 定义（如 `HarnessConfig`、`DeepSeekHarnessConfig`、`Notification`、`IncomingRequest`），以减少内存占用。
- JSON-RPC 消息体统一采用 `json.dumps(message, separators=(',', ':')) + '\n'` 的紧凑行格式写入子进程 stdin。
- 异步 I/O 通过 `threading.Thread` + `queue.Queue` 组合实现：reader/stderr 线程负责读取，主线程通过带超时的队列等待响应或通知。
- 资源清理遵循上下文管理器模式：`HarnessClient`、`NotificationSubscription`、`DeepSeekHarness` 均实现 `__enter__`/`__exit__`，并在 `close()` 中发送 `shutdown` 后强制 terminate/kill。
- 运行时定位采用“显式覆盖优先”策略：优先检查 `config.runtime_bin` / `bridge_bin` / `launch_args_override`，否则回退到 `deepseek_harness_runtime.resolve_bundled_launch_args()`，失败时抛出包含获取指引的 `FileNotFoundError`。
- 通知过滤通过高阶函数 `NotificationFilter: TypeAlias = Callable[[Notification], bool]` 表达，并由 `_notification_belongs_to_session_tree` 等工厂动态生成，支持按 session 树关系匹配。
