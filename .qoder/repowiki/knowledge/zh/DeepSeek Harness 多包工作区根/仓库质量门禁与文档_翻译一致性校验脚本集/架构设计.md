脚本按职责平铺在 scripts/ 根目录，通过 `run-gates.ts` 作为统一入口：以 `Mode`（ci-primary / ci-static / ci-coverage / ci-snapshot / check-all / doc-sync 等）枚举聚合出 Gate 有向无环图，使用内置的 `runGates` 调度器以 `DSH_GATE_CONCURRENCY` 控制并发，并通过 `pnpmScript` / `pnpmExec` 调用各子脚本，所有平台适配由各自 gate 完成而非共享层。

脚本分为四类：
- 门禁编排：`run-gates.ts` + `coverage-exempt.ts` + `package-invariants.ts` 等组合成 CI 流水线；
- 包/代码不变量：`verify-*` 系列（如 `verify-package-invariants.ts`、`verify-cordis-config.ts`、`verify-md-links.ts`、`verify-runtime-closure.ts`）对 package.json、tsconfig、导出、链接、类型等进行静态扫描；
- 文档与翻译：`translation-pairing.ts`、`translation-prompt.ts`、`gen-doc-graphs.ts`、`project-doc-site.ts`、`paired-markdown-derivatives.ts` 等维护中英双语配对、Markdown 衍生产物和文档站点投影；
- 构建/发布辅助：`build-python-release.py`、`build-exe-for-python-sdk.ts`、`publint-all.ts`、`publish-npm-baseline.ts`、`rescope-vendor.ts` 等。

每个脚本通常配套一个同名 `.spec.ts` 单元测试（Vitest），并配合 `fixtures/`、`snapshots/` 中的期望数据；`.sh` 与 `.py` 用于 shell-free 无法覆盖的平台边界（macOS deployment target、bubblewrap、wine gates）。依赖方向单向指向仓库源码与 pnpm workspace，不反向被业务模块引用。
